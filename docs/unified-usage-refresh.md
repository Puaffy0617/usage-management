# 同步状态与官方线程明细

当前 `usage.4` 已改为原生后台采集，页面和焦点不再控制是否采集；同时修复 npm 启动链的控制台子窗口。设置、价格维护和无控制台验证见[后台同步说明](unified-usage-background.md)。下文 `usage.3` 焦点修复是历史背景。

## 同步成功，数字为什么没有变化

账号日汇总来自官方 `account/usage/read`。返回的每日记录只有日期和 Token 总数；模型、请求数、输入/输出及缓存分项不在这份日汇总中。最新已报告日期可能早于今天。重新查询成功并不表示服务已经生成今天的汇总，也没有已验证的实时更新时限。

`4.0.25-usage.3` 在页面顶部持续显示自动刷新是否运行、暂停原因、覆盖的账号数、上次成功检查时间、最新已报告 UTC 日期和精确 Token 总数。`B`、`M` 缩写不适合观察很小的增量；精确数值可以确认变化。一个账号失败时，另一个账号的成功结果会保留，账号行仍显示各自状态。

当前默认每两分钟后台检查所有到期的已连接账号，账号或模型筛选只影响显示。旧版 `usage.3` 在页面可见且窗口活跃时运行，并修复了初始焦点与原生焦点恢复；`usage.4` 已移除这一采集前提，切回页面仅刷新已保存数据的显示。

App Server 连接中断或超时会使用新的临时进程重试一次，保留已收到的有效结果。重试使用同一个短期访问令牌，原账号管理器仍是唯一刷新令牌所有者。普通服务器错误、限流或参数错误不再误报为登录过期；明确的授权失败仍要求从原账号面板处理。导入和同步均不主动退出原账号。

## 已发现线程的官方累计快照

官方 Codex 0.166.0 的公开 App Server 协议支持 `account/usage/read {threadId}`。它通过当前认证账号的官方服务查询线程累计用量，可能返回模型、推理档位、速度、输入/缓存读取/输出/总 Token，以及官方估算美元。接口实际返回哪些字段取决于服务和账号；空响应表示没有可用明细。

该视图单独显示，覆盖范围为**本机已发现线程标识中，官方服务实际返回的累计快照**。应用从 Codex 会话文件的元数据头发现候选标识，再分别通过已有账号的临时认证连接验证。当前选中的账号、创建线程的账号或文件所在日期都不能用于分配全部历史用量。不会导入聊天正文。候选列表也不是完整的云端线程目录。

每个账号每轮最多查询三个候选线程，使用持久化检查时间逐步补齐并刷新。已有快照最短两分钟重新检查，暂时没有明细的线程最短十五分钟重查，临时错误最短五分钟重试；本地线程元数据发生变化时可提前重查。每次线程请求最多十五秒，每个账号的线程查询总预算三十秒；失败不会丢弃成功的账号日汇总。连接中断保留上次成功快照并显示状态。某些线程可能一直没有官方明细，界面会明确显示不可用。

同一线程若在两个账号上下文中都返回快照，其账单归属仍不明确。它不会计入跨账号合计。来源没有给出时间分布，因此这些累计值没有日日期，不受日范围筛选分摊，也不加入上方日汇总或热力图。

## 金额的含义

线程美元金额保留官方字段的含义：`estimatedUsageUsdMicros` 是官方美元估算，`nativeUsageUsdMicros` 是另一项可选的原生美元指标，两者分开展示，不能相加。整数百万分之一美元除以一百万后，才按有效 USD/CNY 汇率换算。积分字段不会换算成美元；缺少美元字段时显示「—」。这些指标不等于 ChatGPT 订阅扣款。

线程模型组没有缓存写入计数，不能把缺少的计数补成零，再套用本地价格表。原来的严格 API 等值估算保留其完整分项要求，详见[费用说明](unified-usage-costs.md)。线程面板使用服务明确返回的美元指标，两种金额来源保持可辨别。
