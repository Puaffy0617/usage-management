# 定制版 GitHub 发布与更新

发布仓库为 [Puaffy0617/usage-management](https://github.com/Puaffy0617/usage-management)，设为公开。它保留上游 CC Switch 的代码与许可，增加多账号用量统计、原账号关联和独立的定制更新通道。

## 使用更新

先安装一次本仓库 Releases 中的定制安装包。此前提供的本地包没有此仓库的信任配置，不能直接接受新通道的自动更新。退出正在运行的 CC Switch 后安装，保留原数据目录和登录信息。

后续启动时，软件检查已固定的定制更新通道；发现新版后提示。进入 **设置 → 关于 → 定制版签名更新** 查看版本，点击验证、安装并重启。安装属于用户主动操作，不会在后台静默替换正在运行的程序。

客户端把仓库、公钥和渠道编译进程序，只接受该仓库、该签名密钥和指定定制版本的更新。它会验证安装包签名和签名中的版本，拒绝篡改、旧包冒充新版和改换下载来源。界面不接收 GitHub 令牌、替代下载地址或替代公钥。官方原版更新仍只作功能合并的输入。

账号保存在原有 CC Switch 数据目录，安装包不携带账号凭据。原版已保存账号由原凭据管理器继续管理，统计视图按账号关联；不调用退出登录。另行授权的独立统计账号继续使用其原有隔离配置路径和系统凭据存储。服务端会话失效或撤销仍可能需要重新授权。

`4.0.25-usage.2` 的账号统计视图增加人民币 API 等值估算、UTC 热力图、账号/模型/每日明细，并默认在页面可见且窗口处于前台时每两分钟刷新全部已连接账号。金额是按已报告 Token 和模型价格计算的估算，不是订阅实际扣款；缺少数据或汇率时保持不可用。操作与覆盖限制见 [费用与自动刷新说明](unified-usage-costs.md)。可安装版本以 Releases 中已发布的产物为准。

`4.0.25-usage.3` 修复原生焦点恢复与临时连接重试，增加持续同步状态、精确总数和单独的官方线程累计快照。数据库仅增加 schema 27 快照表，并将该迁移加入发布前的必需原生检查。覆盖范围与字段限制见 [同步与线程明细](unified-usage-refresh.md)。

## 发布流程

源码中的 `customization/release-channel.json` 固定公开仓库、公钥、`stable` 渠道和定制版本。首次版本格式为 `4.0.25-usage.1`；同一上游版本可增加 `usage.2`、`usage.3`。上游版本另存于 `customization/upstream.json`，不能仅凭应用版本判断原版是否更新。

手动发布工作流以及每周检查工作流使用同一构建校验规则。先在没有签名密钥的任务中检查源码、测试并生成 Windows NSIS 安装包；只有成功产物才能进入单独的签名发布任务。签名任务核对固定配置、版本、来源提交和产物摘要后签名，并发布版本化安装包、公开签名和 `latest.json`。签名密钥存入 GitHub Actions Secret，不写入源码、日志、公开源码包或应用中。

检测上游新稳定版时，工作流尝试在独立目录合并定制改动，保留账号统计和定制更新代码。出现代码冲突、上游数据库版本变化、测试失败或构建失败时停止，不发布该候选版本。此流程无法保证任意未来上游改动都可自动合并。细节见 [源码更新兼容流程](unified-updates.md)。

定制版本虽然使用 SemVer 的 `-usage.N` 标识，GitHub 发布被明确设为正式渠道而非 prerelease，客户端也按自有定制版本规则比较。上游原有发布、同步和机器人工作流仅允许在原官方仓库运行；本仓库使用独立的定制工作流。

## 维护配置

`scripts/configure-release-channel.mjs` 默认预览，添加 `--write` 才会修改配置和统一应用版本。只传入 `.pub` 公钥文件，禁止使用私钥文件：

```powershell
node scripts/configure-release-channel.mjs --repository Puaffy0617/usage-management --public-key-file C:\secure\usage-management.key.pub --version 4.0.25-usage.2 --write
```

更新签名与 Windows Authenticode 证书是不同机制。定制安装包可以通过应用内的签名校验，但不代表已经取得 Windows 发布者证书。首次安装可能显示系统的未知发布者提示。

原项目曾把 Gemini CLI 的 Google OAuth 客户端配置直接写在源码中，GitHub 推送保护会拦截这些字面值。本仓库改用构建配置 `CC_SWITCH_GOOGLE_OAUTH_CLIENT_ID` 和 `CC_SWITCH_GOOGLE_OAUTH_CLIENT_SECRET`，由受保护的 Actions Secret 仅注入 Windows 构建任务；本仓库的托管构建沿用原客户端注册，因此不会更换现有 Gemini 刷新令牌绑定的客户端。它们不属于你的账号令牌，也不会注入独立签名任务。自行构建时若未配置，已有可用访问令牌仍可使用，需要刷新时会显示此构建未配置刷新功能，不删除或注销账号。

签名私钥的原始备份留在本次任务工作目录外于源码的受限文件夹 `work/signing-private`。请将其保存到你控制的安全备份位置；它不包含在公开仓库或交付 ZIP 中。丢失密钥后不能让已有客户端自动信任另一把密钥，需要单独的受信任迁移方案。

真实双账号授权与安装后的账号保留需要在用户设备上验证。本次开发不读取原账号凭据，也不会用新安装包覆盖你当前运行的程序来做测试。
